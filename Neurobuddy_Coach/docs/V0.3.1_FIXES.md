# Neurobuddy v0.3.1: Fix verification

## Upload defect

Previously `v2/shelf-ui.js` attempted the File System Access picker with an HTML file-input fallback and immediately launched the picker from several modal paths. Depending on browser support or rejection, this could produce two selection interactions, and failed uploads only posted errors to a banner behind the modal. The new code uses only the native input, opens it within the user click, retains the selected `File` objects and provides an in-modal Retry action. One successful selection is sufficient to create/populate a shelf.

Browser smoke test: create Team and Athlete; open first shelf, click Add EEG and Downloads, select a real synthetic `.fif` once; observe `Signal uploaded` and closed dialog. The automated Chromium test recorded exactly one filechooser event and no JavaScript exceptions.

## Unnecessary shelf control

Removed the shelf-footer `Select Shelf`. Existing header Open and gear select the shelf, while the Drag / Test EEG control continues to target EEG processing.

## Scientific report display

Stopped rendering limited metric previews in the Analysis panel. Completed runs show links to the pipeline's original HTML reports (and unchanged downloadable ZIP/JSON/CSV). Paths are served using the existing `/api/v2/artifacts/{job_id}/{path}` route. Team-batch runs link each completed athlete's report; skipped athletes retain their error messages.

Browser smoke test: processed synthetic `.fif` through the optimized pipeline, visited Analysis, found an `Open full EEG HTML report` link, confirmed no inline metrics table, and requested the link from the API. Returned HTTP 200, `text/html` with the actual generated report.

## Regression verification

- `node --check v2/shelf-ui.js` and `node --check v2/app.js` both pass.
- `python -m pytest tests/ -q` pass count documented in README (3 optional real-data tests skipped).
- One additional Chromium end-to-end verification used the running FastAPI server and the genuine upload and analysis APIs through an isolated browser bridge. Full real public OpenNeuro integration and cross-browser Safari behavior were not independently tested.
- `neurobuddy_v2/` and `backend/` source code remain unchanged from v0.3, so scientific comparisons and API behavior are preserved.
